## Application architecture
- Next.js App Router with fully static pages. All editable copy lives in `src/content` (brand, SEO, services, projects, FAQ); service and case-study pages are generated from it via `generateStaticParams`, so adding an item creates the page, sitemap entry, JSON-LD and llms.txt line.
- The brand is a 100% online studio serving all of Brazil: never add a city, state or physical address to copy, metadata or structured data (the schema uses `Organization` + `OnlineBusiness` with `areaServed: Brasil`).
- SEO lives in `src/lib/seo`: `pageMetadata` (canonical, OG, Twitter) and `pageGraph` (schema.org graph with stable `@id`s). Every public page renders one `h1`, visible breadcrumbs and its own JSON-LD.
- There are no forms and no database: every CTA is a `WhatsAppLink`, which carries `data-cta` attributes that a single document-level `InteractionTracker` turns into `whatsapp_click` (and `demo_click`) dataLayer events for GTM.
- Shared motion is progressive enhancement: `useSiteMotion` (mounted once in the root layout, re-run per route) reveals `[data-reveal]` elements with native observers; without JS or with reduced motion everything stays visible.
- Commercial terms and WhatsApp URL generation live in one browser-safe module (`src/lib/pricing/commercial.ts`) shared by pricing sections, service pages, structured data and llms.txt, so displayed fees and destinations stay consistent and testable. Price text written in `src/content` is checked against that module by `src/tests/unit/content.test.ts`: adding a new price means adding it to the allowed list there.
- The home page is a conversion page, not a catalogue: it shows 3 plan cards (`PlansSection variant="summary"`) and sends details to `/servicos#planos` (`variant="full"`). Keep at most two consecutive sections without a WhatsApp button (tested in `src/tests/integration/conversion.test.tsx`). The example report uses fictitious data and must always say so.
- The deposit ("sinal") retention rule lives only in the proposal and contract templates (`~/projetos/solid-solutions-modelos`), never on the site. When prices or terms change here, update those templates too.
- Hosting is included in plans with a site and never depends on the R$ 50 maintenance fee.
- Vitest compiles JSX itself (`oxc` option in `vitest.config.ts`) because Next forces `"jsx": "preserve"`. CI (`.github/workflows/ci.yml`) runs typecheck, lint, tests and build; `scripts/smoke.mjs` tests the published site after each production deploy.
- Keep the official palette (tokens in `src/styles/base.css`) and the official logo files in `src/assets/brand` / `public/brand`.
